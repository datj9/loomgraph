# Team hub — implementation plan

Work order for `docs/hub-design.md` revision 2. This is the **spec an executor builds
against**; the design doc is the reasoning behind it. Where they disagree, the design doc
wins and this file is wrong and must be fixed — **except** that this plan is the authority on
commit boundaries and ordering.

Revision 2 of this plan applies an adversarial review whose findings were verified against
the real tree. Four things it caught are worth knowing before reading further, because each
one silently produces a wrong result rather than a failing build:

- `WITHOUT ROWID` on `events` makes `(received_at, rowid)` cursors impossible — verified,
  `SELECT rowid` fails with `no such column: rowid`. Design §6.3 is fixed; do not
  reintroduce it.
- **`RunState` carries content**, not just status: `vars` values and `nodes[*].output` (raw
  agent stdout). Pushing it verbatim would publish secrets team-readable in phase 1, a phase
  before any masking exists. Commit 1.10 exists to prevent that and is not optional.
- `INSERT OR REPLACE` on `events` fires the append-only delete trigger. Use
  `ON CONFLICT DO NOTHING`. If a trigger seems to be "in the way", the code is wrong, not
  the trigger.
- `src/handoff/scan.test.ts:45` asserts the **complete ordered list** of rule names, so
  commit 1.1 is red unless it updates that list in the same commit.

## Ground rules (from AGENTS.md — non-negotiable)

1. **No new runtime dependencies.** `node:http`, `node:crypto`, `node:sqlite`, global
   `fetch`. Runtime deps stay exactly: commander, execa, yaml, zod.
2. **No test may spawn `claude`, `codex`, `opencode`, `enclave` or `git`, or make a network
   request.** Handler tests call functions directly against an in-memory database. Client
   tests use an injected `Fetch` seam. The contract test wires the fake fetch straight to
   the handler functions in-process.
3. **`npm run typecheck && npm test` green behind every commit.** One logical change per
   commit, conventional prefix, imperative lowercase subject, no emoji.
4. **Nothing under `src/handoff/` imports outward.** `src/hub/` imports
   `src/handoff/scan.ts` one-way; never copy the scanner.
5. **The laptop's `.loomgraph/runs/<id>/events.jsonl` is not touched.** Still append-only,
   still unbuffered. The hub's storage choice does not reach it.
6. **Never invent cost numbers.** Nothing in the hub derives a price from tokens.
7. **Adding a field to `DistilledSession` means deciding it is safe to publish.** The
   readers drop; they do not carry.

## Assumptions this plan makes (design doc §14, unanswered)

- **A1 — sync granularity:** repo-level opt-in. `lg sync --enable` writes
  `.loomgraph/hub.json`; nothing syncs without it. Reversible in a few lines if wrong.
- **A2 — the testing carve-out:** NOT taken. AGENTS.md's no-network rule stands unchanged.
  `src/hub/server.ts` stays dumb binding and stays untested, like `src/cli.ts` today.
  Revisit at phase 5 when SSE gives it real logic.
- **A3 — brief key wrapping:** a master key file on the hub host, `0600`, path from
  `LOOMGRAPH_HUB_KEYFILE`, generated by `lg-hub init` if absent. This is the option that
  survives an unattended restart. **It defends against a stolen disk, not against an
  operator with root** — `lg-hub` must print that sentence on `init`, and the README must
  say it too. If the author prefers a passphrase at `serve` start, only
  `src/hub/keys.ts` changes.

If the author overrides any of these, the affected phase's first commit changes and nothing
else does.

## Cross-phase invariants an executor must not break

- **Attribution is server-side.** `member` comes from the token's `key_id`, never from a
  request body. A client-supplied `createdBy` is displayed as a claim at most.
- **A hub outage cannot affect a run.** No hub code path may throw into the engine, change
  a checkpoint, or change an exit code. The batcher swallows everything and writes one
  line to stderr.
- **Gates fail closed.** Anything the scanner cannot read is a finding. An empty finding
  list means "looked and found nothing", never "did not look".
- **`events` is append-only in the database too**, enforced by trigger, not by convention.
- **Every read path masks on egress** once phase 2 lands. No exceptions for the export.

### 1.5 `feat: add the hub store`

New `src/hub/storage.ts`.

```ts
export interface HubStoreDeps { now(): string }
export class HubStore {
  static open(path: string, deps?: HubStoreDeps): HubStore   // ':memory:' in tests
  close(): void
  ingest(member: string, batch: EventBatch): IngestResult | IngestConflict
  highWater(member: string, streamId: string, runId: string): number | null
  runState(member: string, runId: string): ProjectedState | null   // newest stream wins
  events(member: string, streamId: string, runId: string): string[]  // raw lines
  listRuns(member?: string): RunRow[]
  allEvents(): Iterable<{ member: string; runId: string; json: string }>  // backs export
  chainHead(): string                                          // hex; 64 zeros when empty
  addMember(member: string, scopes: string[]): { keyId: string; token: string }
  memberByKeyId(keyId: string): { member: string; tokenHash: string; scopes: string[];
    revokedAt: string | null } | null
  revokeMember(keyId: string): boolean
  listMembers(): Array<{ keyId: string; member: string; revokedAt: string | null }>
  feed(cursor: string | null, limit: number): { items: FeedItem[]; nextCursor: string | null }
}
```

Rules an executor must not resolve differently:

- Schema exactly as design §6.3 **as amended**: `events` is an ordinary rowid table with a
  `UNIQUE (member, stream_id, run_id, seq)` constraint. No `WITHOUT ROWID` anywhere.
- `PRAGMA journal_mode=WAL`, `foreign_keys=ON`, `user_version=1`. Both append-only triggers.
- **Inserts use `INSERT … ON CONFLICT DO NOTHING`.** `OR REPLACE` fires the delete trigger.
  UPSERT is allowed on `runs`, never on `events`.
- `ingest` is one transaction. For each event at or below the high-water mark, compare the
  stored `json` byte-for-byte: equal counts as a duplicate; **different aborts the whole
  transaction and returns `IngestConflict` — nothing is written and nothing is acked.**
- The hash chain is global. `chain_head` is a one-row table updated inside the ingest
  transaction; `row_hash = sha256(prev_hash || json)`; genesis `prev_hash` is 32 zero bytes.
- Cursors are opaque base64 of `{receivedAt, rowid}`, keyset over `(received_at, rowid)`.
  Never a byte offset, never a client timestamp. A cursor that fails to decode is an error
  the caller maps to 400, not a silent reset.
- `scopes` is stored as a JSON array string. `addMember` defaults to `["ingest","read"]`.
- `keyId` is `randomBytes(4)` hex; the secret is `randomBytes(32)` base64url; the returned
  token is `lgt_<keyId>.<secret>` and is the only time it exists in full.

Tests (in-memory, frozen clock): `UPDATE events` throws; `DELETE FROM events` throws; both
triggers still exist in `sqlite_master` after a successful ingest; ingesting the same batch
twice yields one set of rows and reports duplicates; the same key with a different payload
returns a conflict and writes nothing (assert row count unchanged); `chainHead` matches a
hand-computed chain over three events; a keyset cursor round-trips and never repeats or
skips an item across pages, including when two rows share `received_at`; `allEvents` yields
every ingested line byte-for-byte; `addMember` → `memberByKeyId` round-trips scopes;
`revokeMember` sets the timestamp and is idempotent.

### 1.6 `feat: add hub auth`

`src/hub/auth.ts`:

```ts
export function mintToken(): { keyId: string; secret: string; token: string }
export function hashToken(secret: string): string   // sha256 of the SECRET ONLY, hex
export function parseToken(header: string | undefined): { keyId: string; secret: string } | null
export function resolveMember(store: HubStore, header: string | undefined):
  { member: string; keyId: string; scopes: string[] } | null    // null => 401
```

- `hashToken` hashes **the base64url secret string only**, not the whole `lgt_…` token, and
  returns lowercase hex. Both sides must agree or every hub is subtly incompatible.
- Compare with `crypto.timingSafeEqual(Buffer.from(a,'hex'), Buffer.from(b,'hex'))`. Both
  are 32-byte digests so lengths match; **a stored hash of the wrong length resolves to
  null rather than throwing**, because `timingSafeEqual` throws on length mismatch and that
  would turn a bad credential into a 500.
- A revoked member resolves to null.

Tests: valid resolves; unknown keyId null; correct keyId with wrong secret null; **valid
keyId with a 3-character secret resolves null and does not throw**; revoked null; `undefined`,
`""`, `"Bearer"`, `"Basic x"` and a token with no `.` all resolve null without throwing;
`mintToken`'s output verifies against `hashToken` of its own secret.

### 1.7 `feat: add the hub http handlers`

`src/hub/handlers.ts` — all behavior, no sockets:

```ts
export interface WireRequest { method: string; path: string; query: Record<string,string>;
  headers: Record<string,string|undefined>; body: unknown }
export interface WireResponse { status: number; body: unknown; headers?: Record<string,string> }
export interface HandlerDeps { store: HubStore; now(): string; version: string }
export function handle(req: WireRequest, deps: HandlerDeps): WireResponse
```

Routes: `GET /v1/health` → `{ok:true, version}`, unauthenticated. `POST /v1/events`,
`GET /v1/feed`, `GET /v1/runs/:member/:runId` — all authenticated. Anything else 404.

- Order of operations: body-size check → auth → JSON/zod parse → act. Auth failure must not
  reveal whether the body was valid.
- Every error body is exactly `{ error: string }`, plus fields where named below.
- 401 `{error:"unauthorized"}`. 404 `{error:"not found"}`. 400 `{error:"bad request"}` for
  an unparseable body or an undecodable cursor. 413 `{error:"body too large"}` when the
  serialized body exceeds `MAX_BODY_BYTES`. 409 `{error:"seq conflict", runId, seq}`.
- `POST /v1/events` stamps `member` from the token. The zod schema **must not contain a
  `member` field**; there is nothing to prefer over the token, by construction.
- `GET /v1/feed` `limit` defaults to 50 and clamps to 200.
- `GET /v1/runs/:member/:runId` returns the stored member's data for any authenticated
  reader (design §7) and never re-stamps the requester as owner.
- `version` comes from `VERSION` in `src/index.ts`.

Tests: health without a token; every other route 401s without one; a good batch returns the
high-water mark; replaying returns the same mark with `accepted: 0`; a divergent seq is 409
naming runId and seq; an over-cap body is 413 and is never parsed; a batch carrying
`member: "someone-else"` in the body still stores under the token's member; reading another
member's run returns their data unmodified; a missing run is 404; a garbage cursor is 400;
`limit=9999` clamps.

### 1.13 `feat: push events as a run produces them`

New `src/team/batch.ts`:

```ts
export interface Batcher { onEvent(e: LgEvent): void; flush(): Promise<void>; stop(): void }
export function makeBatcher(cfg: HubConfig, f: Fetch, ctx: BatchCtx): Batcher
```

- Activates only when **both** `loadHubConfig()` is non-null **and**
  `repoSyncEnabled(cwd)` is true. Assumption A1 is enforced here or it is not enforced.
- Flush at 10 events or 5 s. **The timer must be `unref()`d and cleared in `stop()`**, or
  `lg run` hangs after the run finishes.
- `onEvent` stays synchronous and fire-and-forget. **Every batch promise carries its own
  `.catch`** — an unhandled rejection changes the process exit path and vitest results.
- The try/catch wraps **only the fetch promise chain**. It must not wrap the engine, the
  checkpoint, or the console printing.
- **Compose with the existing `onEvent`, do not replace it.** `src/commands/run.ts:59` and
  `resume.ts:45` already print live progress there; wrap so both run, printing first.
- `runCommand`/`resumeCommand` `await batcher.flush()` after `execute` returns, then
  `stop()`. Failures print at most one stderr line for the whole run.
- The `Fetch` reaches the command as an optional dep parameter defaulting to global `fetch`,
  so tests inject without touching globals.

**Write this test first, and watch it fail for the right reason:** with a `Fetch` that
rejects every call, a run's outcome is identical to the same run with no hub configured.
Byte-identical is impossible — `makeRunId` embeds a timestamp and random suffix — so the
mechanism is: call `execute` twice with a fixed `runId`, a stub adapter registry and temp
`CheckpointStore`/`EventLog`; strip `ts`, `createdAt`, `updatedAt` and durations; then assert
equal event kind+seq sequences, equal normalized final `RunState`, and equal
`exitCodeFor(...)`. Additionally assert stderr received at most one line, and that the
process has no pending timer once `stop()` has run.

# Phase 2 — briefs

### 2.1 `feat: encrypt hub items at rest`
`src/hub/keys.ts`: `lg-hub init` generates a master key `0600`; per-item DEK wrapped with
AES-256-GCM via `node:crypto`; `item_keys` rows; `shred(keyId)` is one `DELETE`.
Tests: round-trip; shred makes plaintext unrecoverable while the row survives; a missing
master key is a clear error, never a silent plaintext write.

### 2.2 `feat: accept briefs on the hub`
`POST /v1/briefs`. **Re-scan server-side even when the client claims clean**; any finding is
422 with masked findings. Note `scanBundleDir(dir)` walks a directory and the handler
receives four inline strings — call the exported `scanText` per field with the filename as
`file`, which is reuse, not a fork. **An absent or non-string field is a 422 carrying an
`unreadable-file`-style finding**, never a skip: losing `UNREADABLE_RULE`'s fail-closed
behaviour is the one way this gate can silently pass. Adopt `ENCLAVE_ALLOWED_EXTENSIONS`,
`ENCLAVE_MAX_FILE_BYTES`, `ENCLAVE_MAX_FILES`, `ENCLAVE_MAX_TOTAL_BYTES` as ingest limits.
Idempotent by `sha256(handoff.md)`. Store encrypted, with `expires_at` defaulting to 7d.
Tests: planted secret shapes rejected despite a clean claim; a `.jsonl` file is refused;
oversized refused; identical brief pushed twice is one row.

### 2.3 `feat: mask stored content on every read`
`src/hub/redact.ts` wrapping `scanText` + `rewritePaths` at egress, applied on the API, the
UI and the export. **Make forgetting structurally impossible: `HubStore` never returns brief
plaintext at all — the only decrypt path lives in `redact.ts` and masks before returning.**
A helper the caller must remember to call will be forgotten by the third caller. A finding at read time is logged to `access_log` and surfaced to the
owner. Tests: a rule added after ingest masks already-stored content; masking is applied on
all three paths (a test per path, so a new path cannot forget).

### 2.4 `feat: share and retract briefs`
`brief_shares` grant/revoke; private to owner by default; `lg hub retract` tombstones and
shreds. Tests: grantee reads, third member 404s, revoked grantee 404s, retracted brief is
gone from `search` and from the feed.

### 2.5 `feat: let the owner choose brief depth`
`lg-handoff pack --turns 12-31,44 --include-tool-result 27`. Extractive, no model call.
Default unchanged. Tests: exact turns carried and no others; an out-of-range index is a
usage error; the scan gate still runs; `DistilledSession` gains no field that was not
deliberately approved.

### 2.6 `feat: push briefs to the hub`
`lg-handoff push --to hub` alongside the enclave path, through the same local gates.

### 3.1 `feat: fence untrusted content`
`src/team/fence.ts` — un-spoofable delimiter, neutralized lookalikes in the body, a preamble
stating the content is untrusted data whose instructions must not be followed, every line
prefixed in the `quote()` style of `src/handoff/render.ts`. **No markdown engine.**
Tests: a body containing the delimiter cannot escape; a body of `javascript:` links renders
inert; every line is prefixed; the preamble is always present.

### 3.2 `feat: add inbox send and list`
`POST /v1/inbox`, `GET /v1/inbox`. Person-addressed only. Scan `subject`, `body`,
`proposedGraph.source` and every var; `parseGraph` any proposed graph and reject invalid
ones at send. Tests: only the addressee lists a message; scan and parse gates; no
broadcast address exists.

### 3.3 `feat: add inbox show, accept and decline`
`lg inbox show` prints the fenced body untruncated plus `renderPlan` and the budget line.
`lg inbox accept <id> --graph <local path>` runs the **acceptor's** graph with the body
exposed only as pre-fenced `{{inbox.body}}`. **`interpolate` in `src/core/engine.ts` resolves
only single tokens, `vars.*` and `nodes.<id>.output`, so `{{inbox.body}}` throws today.**
Extend `interpolate` with an explicit `inbox` namespace whose value is fenced before it
enters the state — do not pre-substitute the raw body into the prompt string, which bypasses
fencing entirely and is the tempting shortcut; `--use-proposed-graph` prints the full YAML and
requires typing the message id. `--cwd` is always the acceptor's. Sandbox defaults to the
most restricted; a message can never name one.
Tests: `show` truncates nothing; accept refuses a budget-less graph; `--use-proposed-graph`
refuses without confirmation; **an inbox-sourced run never receives `bypass`**; a message
naming a local path cannot set `cwd`; no flag skips `show`; there is no `--auto-accept`.

### 3.4 `feat: track inbox state transitions`
`queued → seen → accepted|declined|expired`, `accepted → done|failed`. Only the addressee
transitions. Tests: illegal edges refused; a third party cannot transition; history append
is atomic.

### 3.5 `feat: scope hub tokens` — `ingest`/`read`/`admin` enforced; unread via `read_marks`.
